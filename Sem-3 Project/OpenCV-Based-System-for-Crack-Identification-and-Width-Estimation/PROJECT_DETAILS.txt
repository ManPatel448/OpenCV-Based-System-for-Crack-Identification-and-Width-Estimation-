1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
Project Name    : OpenCV-Based System for Crack Identification and Width Estimation
Primary Purpose : Automated identification, continuous segmentation, centerline 
                  skeletonization, width measurement, and severity classification 
                  of surface cracks on concrete, asphalt, roads, and walls.
Frontend UI     : Web-based interface (HTML5, Bootstrap 5, CSS3, Vanilla JS)
Backend Engine  : Python (Flask Framework, OpenCV, NumPy, Scikit-Image)
Database        : MongoDB (with automatic in-memory fallback if MongoDB is offline)

2. WHAT TYPE OF MODEL IS USED IN THIS PROJECT?
================================================================================
A frequent question is: "Does this project use a Deep Learning model (like YOLO, 
U-Net, CNN) or what type of model does it use?"

ANSWER:
This project uses a **Deterministic Classical Computer Vision (CV) Mathematical 
& Morphological Pipeline Model**, combined with a **Rule-Based Decision Classifier 
Model** for severity assessment. It does NOT require a heavy neural network or 
GPU.

Why this model approach was selected:
1. Fast Execution (CPU-Only): Runs in milliseconds per image without high-end GPUs.
2. Complete Mathematical Explainability: Every width sample is calculated using 
   exact Euclidean Distance Field geometry, not black-box neural approximations.
3. No Huge Training Dataset Needed: Works directly on concrete and asphalt 
   surfaces using physical structural characteristics of cracks.
4. Deterministic & Calibrated: Direct 1-to-1 conversion between image pixel 
   coordinates and real-world millimeters (mm).

The 9 Mathematical & Algorithmic Models Used:
--------------------------------------------------------------------------------
(1) PHOTOMETRIC ENHANCEMENT MODEL:
    - Algorithm: CLAHE (Contrast Limited Adaptive Histogram Equalization)
    - Library  : cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8, 8))
    - Purpose  : Normalizes shadows, lighting gradients, and enhances crack 
                 fissure contrast against pavement aggregate stones.

(2) MORPHOLOGICAL BLACK-HAT FEATURE EXTRACTION MODEL:
    - Algorithm: Black-Hat Transform = Closing(I) - I
    - Kernel   : Elliptical Structuring Element (21x21)
    - Purpose  : Mathematical morphology specifically formulated to isolate narrow 
                 dark structures (cracks) that are darker than the local background.

(3) ADAPTIVE GAUSSIAN SPATIAL THRESHOLDING MODEL:
    - Algorithm: cv2.adaptiveThreshold(ADAPTIVE_THRESH_GAUSSIAN_C, THRESH_BINARY_INV)
    - Formula  : T(x, y) = Local_Gaussian_Mean(x, y) - Offset (C)
    - Purpose  : Handles non-uniform lighting across roads/slabs by calculating a 
                 dynamic threshold for every 41x41 neighborhood.

(4) TOPOLOGICAL GAP BRIDGING & CONTINUITY MODEL:
    - Algorithm: Morphological Closing (cv2.MORPH_CLOSE, kernel size 3x3 to 5x5)
    - Purpose  : Connects fine crack segments broken up by road aggregate stones 
                 without eroding thin crack necks (eradicating fragmentation).

(5) COHERENT GRAPH LINKING & PATH UNIFICATION MODEL:
    - Algorithm: Component Proximity Graph & Minimum Distance Bridging
    - Distance : Parameterized link distance (crack_link_distance_px = 25.0 px)
    - Purpose  : Unites fragmented crack components lying along the same physical 
                 crack pathway into ONE single continuous crack structure.

(6) GEOMETRIC FILTERING MODEL (SVD + ROTATED RECTANGLE):
    - Algorithm: SVD (Singular Value Decomposition) Principal Component Ratio
    - Formula  : Ratio = sigma_1 / sigma_2
    - Purpose  : Rejects non-crack blobs (gravel stones, circular pits, oil marks).
                 Only regions with aspect ratio >= 3.0 or principal ratio >= 3.0 
                 are classified as cracks.

(7) MEDIAL AXIS SKELETONIZATION MODEL:
    - Algorithm: Topological Medial Axis Thinning (Zhang-Suen / Lee algorithm)
    - Library  : skimage.morphology.skeletonize
    - Purpose  : Reduces the multi-pixel crack mask down to an exact 1-pixel-wide 
                 centerline tree to compute true physical crack length.

(8) EUCLIDEAN DISTANCE TRANSFORM WIDTH MODEL:
    - Algorithm: cv2.distanceTransform(mask, cv2.DIST_L2, 5)
    - Mathematical Principle:
      The distance transform assigns every foreground pixel its exact Euclidean 
      distance to the nearest background border.
      Along the skeleton centerline:
      Width = 2 * Distance_Radius
    - Statistics: Uses the Median for Mean Width (to resist blob outliers) and the 
      95th Percentile for Maximum Width.

(9) RULE-BASED SEVERITY CLASSIFICATION MODEL:
    - Evaluates measured crack widths against configurable physical thresholds:
      * GOOD   : Mean Width <= 3.0 px (or <= 0.300 mm at 10 px/mm)
      * MEDIUM : Mean Width > 3.0 px and <= 8.0 px (0.300 mm - 0.800 mm)
      * HEAVY  : Mean Width > 8.0 px (or Area >= 5000 px^2)

4. DATABASE MODELS & SCHEMA
================================================================================
The project uses three main document collections/models:

1. Analysis Model (`models/analysis_model.py`):
   - `analysis_id`               : Unique UUID hex string for the session.
   - `analysis_name`             : Display title (e.g., "Crack image analysis").
   - `created_at`, `updated_at`  : ISO timestamps.
   - `status`                    : "Uploaded", "Processing", "Completed", "Failed".
   - `total_images`              : Number of images in this batch.
   - `total_detected_regions`    : Total count of identified cracks across batch.
   - `calibration_enabled`       : True / False.
   - `pixels_per_mm`             : Calibration ratio (default: 10.0 px/mm).
   - `processing_configuration`  : Dictionary of algorithm thresholds used.
   - `severity_thresholds`       : Good / Medium / Heavy cutoff rules.

2. Image Model (`models/image_model.py`):
   - `image_id`                  : Unique UUID for the image.
   - `analysis_id`               : Foreign key linking to parent analysis.
   - `original_filename`         : Uploaded file name (e.g., "069.jpg").
   - `stored_filename`           : Disk file name on server storage.
   - `image_width`, `image_height`: Dimensions after scale normalization.
   - `resize_scale`              : Scale factor applied during load.
   - `processing_status`         : "Uploaded", "Completed", "Failed".
   - `workflow_times`            : Step-by-step performance timings in seconds:
                                   * resize
                                   * preprocessing
                                   * detection
                                   * measurement
                                   * annotation
   - `processed_paths`           : Storage paths to intermediate output images:
                                   * resized, gray, blurred, clahe, blackhat, 
                                     binary, cleaned_mask, segmentation_mask, 
                                     skeleton, distance_transform, width_estimation.
   - `annotated_path`            : Storage path to final annotated color image.

3. Measurement Model (`models/measurement_model.py`):
   - `crack_id`                  : Formatted identifier (e.g., "9596e6e2-1").
   - `analysis_id`               : Foreign key to parent analysis.
   - `image_id`                  : Foreign key to parent image.
   - `contour_area_px`           : Total crack area in square pixels (px^2).
   - `contour_area_mm2`          : Calibrated crack area in square millimeters (mm^2).
   - `skeleton_length_px`        : Centerline length in pixels (px).
   - `skeleton_length_mm`        : Calibrated centerline length in millimeters (mm).
   - `mean_width_px`             : Median orthogonal width in pixels.
   - `mean_width_mm`             : Calibrated median width in millimeters.
   - `max_width_px`              : 95th percentile peak width in pixels.
   - `max_width_mm`              : Calibrated peak width in millimeters.
   - `width_sample_count`        : Total number of measurement probe lines.
   - `measurement_points`        : Array of sample point objects (x, y, angle, width).
   - `severity`                  : Categorical classification ("Good", "Medium", "Heavy").

5. END-TO-END PROCESSING PIPELINE (STEP-BY-STEP)
================================================================================

Step 1: Ingestion & Dimension Normalization
   - Input image loaded via `cv2.imread()`.
   - Scaled down proportionally if dimension exceeds `resize_max_dimension` (1600 px).

Step 2: Grayscale & Noise Suppression
   - Converted to single-channel 8-bit grayscale (`cv2.cvtColor`).
   - Gaussian Filter (`cv2.GaussianBlur` 5x5) eliminates sensor noise.

Step 3: Contrast Enhancement
   - CLAHE with 8x8 tiles and clipLimit=2.0 redistributes local histogram peaks,
     enhancing crack definition under non-uniform illumination.

Step 4: Morphological Valley Detection (Black-Hat)
   - Closing with 21x21 ellipse minus original image yields bright ridges where 
     dark cracks existed, suppressing smooth pavement background.

Step 5: Local Adaptive Binarization
   - Gaussian adaptive thresholding evaluates 41x41 pixel neighborhoods to extract 
     crack pixels independent of global asphalt shade variations.

Step 6: Gap Bridging & Noise Cleaning
   - Morphological closing connects small gaps caused by aggregate stones.
   - Connected components analysis rejects isolated fragments smaller than 
     `minimum_region_area` (30 px).

Step 7: SVD & Geometric Crack Verification
   - Elongation analysis via SVD and rotated bounding boxes filters out round gravel 
     and texture stains (minimum aspect ratio >= 3.0).

Step 8: Coherent Crack Path Unification
   - Fragments belonging to the same continuous crack path within link distance 
     are mathematically merged into a single coherent crack component.

Step 9: Skeletonization & Medial Centerline
   - Scikit-Image skeletonize extracts the 1-pixel medial axis tree.
   - Centerline arc length is computed by 8-connectivity pixel walking.

Step 10: Orthogonal Distance Transform Width Estimation
   - L2 distance transform calculates the shortest distance from skeleton to edge.
   - At sampled intervals, tangent vectors are computed and orthogonal lines 
     are cast across the crack profile to measure true physical width.

Step 11: Calibration & Visual Annotation
   - Measurements converted to millimeters using configured `pixels_per_mm`.
   - Results rendered onto the original image: red contours, yellow perpendicular 
     width lines, and blue crack identifier labels.

7. USER INTERFACE & NAVIGATION MENU
================================================================================
The web navigation menu is streamlined to two primary views:
1. "Upload"  (`/upload`)  : Start a new crack analysis. Upload one or more road,
                           concrete, or pavement images.
2. "History" (`/history`) : View all previous inspections, status, total detected
                           cracks, and open results.

From the Results page (`/analysis/<id>`), users can:
- Zoom and inspect high-resolution images with interactive zoom controls.
- View step-by-step intermediate OpenCV stages (Grayscale, CLAHE, BlackHat, 
  Binary, Skeletons, Distance Field).
- Inspect the measurement table showing Length, Area, Mean Width, Max Width 
  in both Pixels (px) and Millimeters (mm).
- Download inspection reports directly as CSV, PDF, or complete ZIP packages.
